# Agentic Engineering

## 要点

- AIエージェントに実装、検証、改善を任せつつ、人間が設計、レビュー、意思決定を担う開発様式。vibe coding の感覚を、エンジニアリング規律へ引き戻す概念。
- `ビル格` では、Chatbot の hallucination が Agent 化すると「文章の間違い」から「行動の間違い」（入居判断、契約説明、Wiki 更新、外部発信）へ拡大する。自律 Agent では間違いが再生産・配布される（権限を持った hallucination）。
- 深津貴之の対談では、AIを無限に働く部下として扱い、人間が何を頼むか、どう評価するか、どこに責任を持つかを設計する視点が強調される。
- `メタスキル` 再ingest では、AIチーム術として、完成物だけでなく迷い、比較、捨てた案、判断基準のログを残すことが強調される。Agentic Engineering は、この判断ログを運用資産に変える実務でもある。
- 経営者向け記事では、技術判断やデザイン判断を上流工程に入れること、責任者や外部アドバイザを経営層に接続することが、職能を組織へ入れる条件として示される。

## 定義または輪郭

- 2026-05-28 の一括 ingest で立ち上がった横断概念。
- 複数 source を束ねるための中間ノードとして扱う。
- 自分の作業手順をモジュール化し、AIエージェントに渡すときの設計・検証・責任分界を扱う。
- 技術やAIを現場の便利ツールで終わらせず、経営判断・上流工程・投資配分に入れる組織設計も含む。

## 緊張関係 / 異説

- AIを部下化するほど、人間側には上司としての目的設定、レビュー責任、安全確認、現実への接続責任が残る。
- ログ化されていない判断は、AIチームに引き継げない。逆に何でもログ化すると、判断より記録が目的化する。
- 技術判断を上流に入れられない組織では、Agentic Engineering が局所効率化に止まりやすい。
