# LLM Wiki 解説まとめ

[元動画（mh_shortly）](https://www.youtube.com/watch?v=it8v6GNxBDI)

## 一言でいうと

**生のメモ・PDF・記事を一度AIに整理させ、リンク付きWikiとして蓄積する仕組み。質問のたびに生データを探し直すのではなく、事前に整理された知識ベースから答える。Andrej Karpathyが2026年4月に提唱し、54,000いいねを集めたパターン。**

---

## 1. 優秀な研究者はどう働くか

優秀な研究者は、質問に答えるたびに論文を最初から読み直さない。

- ノートや頭の中に**知識ベース**を構築する
- 要約、相互参照、つながりを整理する
- 各知識に「場所」があり、その場所が理解を助ける
- 新しい資料は上に積むだけでなく、**既存の知識と接続**される
- 以前の信念を**覆す・更新する**点も記録する

**→ AIにも同じことができる。セッションごとにリセットされるチャットボットではなく、成長し続ける知識ベースを維持する。**

---

## 2. LLM Wiki とは

2026年4月2日、**Andrej Karpathy**（元Tesla AI責任者、OpenAI創業チーム）が1投稿で提唱。54,000いいね超。

**パターンは驚くほどシンプル：**

> 質問のたびに生ドキュメントを検索させるのではなく、**一度AIにWikiとして整理させ、新しい資料が来たら更新し続ける。**

結果：**個人の知識ベースが時間とともに豊かになる。** 永続的なWikiで、AIが構築・維持する。

---

## 3. フォルダ構成（2フォルダ + 1設定ファイル）

| フォルダ/ファイル | 役割 |
|-------------------|------|
| **`raw/`** | ソース素材（記事、PDF、スクショ、メモ）。AIは読むが**変更しない** |
| **`wiki/`** | AIが書き・維持する整理された知識ベース |
| **`schema.md`** | 設定ファイル。**最重要**。知識ベースのテーマ、構造、ルールを定義 |
| **`outputs/`**（任意） | Wikiから生成したレポート・回答を保存 |

**schema.md が最重要** ─ AIに「何について」「どう構造化するか」「どんなルールか」を伝える。

### 初回セットアップの指示例

```
schema.md を読んで。
raw/ の中身を全部処理して。
index.md を作り、トピックごとにWikiページを1つずつ作って。
関連トピックはリンクして。
```

→ 完了すると、整理された相互リンク付きWikiができる。自分では気づかなかったつながりや、忘れていた内容の要約も含まれる。

---

## 4. 3つの操作

| 操作 | 内容 |
|------|------|
| **Ingest（取り込み）** | 新しいソースを `raw/` に入れる → AIが読み、Wikiページを作成/更新、相互参照を追加、**矛盾をフラグ** |
| **Query（問い合わせ）** | 整理済みWikiに対して質問 → AIが事前整理された知識から**合成して回答** |
| **Lint（健康診断）** | 月1回のメンテ。AIが**矛盾・古い主張・空白**を検出。長期的な信頼性を保つ |

---

## 5. LLM Wiki vs RAG

| | **RAG** | **LLM Wiki** |
|---|---------|--------------|
| 仕組み | ドキュメントをチャンク化 → ベクトルDB → 質問時に関連断片を取得 | 一度処理してWiki化 → 質問時は整理済み知識から回答 |
| 蓄積 | **何も蓄積しない**。毎回ゼロから再構成 | 知識は**一度処理され、要約・相互参照がコンパイル済み** |
| インフラ | ベクトルDB、埋め込みパイプラインが必要 | **Markdownファイルだけ** |
| 透明性 | 中身が見えにくい | **閲覧・検証・編集可能** |
| 移植性 | プラットフォーム依存 | **どのツール・AIモデルでも読める** |
| 向いている規模 | 数千ドキュメント、リアルタイムデータ、大規模コーパス | **個人規模（100〜200ソース程度）** |

**RAGは万能ではないが、大規模・リアルタイム用途では依然として有効。LLM Wikiは個人の深い研究・学習に最適。**

---

## 6. Karpathyが挙げた4つの利点

| 利点 | 意味 |
|------|------|
| **Explicit（明示的）** | AIが何を知っていて何を知らないか、**正確に見える** |
| **Yours（自分のもの）** | データは**自分のPC**に。クラウドプロバイダーに預けない |
| **File over app** | **Markdownファイル**。特定プラットフォームにロックインされない |
| **Bring your own AI** | Claude、GPT、オープンソースモデル、**いつでも切り替え可能**。データとAIモデルは完全に分離 |

---

## 7. 始め方（約30分）

1. **2フォルダ作成**（+ outputs/ 任意）
2. **`raw/` にソースを放り込む**（記事、メモ、PDF）。整理不要。それはAIの仕事
3. **`schema.md` を書く** ─ テーマ、フォルダ構造、Wikiルール、フォーカス領域（テンプレート多数あり）
4. **AIエージェントツールを開き**、フォルダを指定して schema に従ってWikiを作成させる

---

## 8. 活用例

- **論文の深い研究** ─ 数十本の論文を横断的に整理
- **コンテンツ制作パイプライン** ─ 調査結果をWiki化して記事・動画に活用
- **書籍シリーズの追跡** ─ キャラクター・テーマページをリンク
- **個人Wikipedia** ─ メモやメッセージから人生の記憶を構造化・検索可能に

---

## 実践的な示唆

1. **チャットボット ≠ 知識ベース** ─ セッションごとにリセットされるAIでは、知識は蓄積しない
2. **一度整理、何度も使う** ─ Ingestで取り込み、Queryで問い合わせ、Lintでメンテ
3. **schema.md が設計の核心** ─ ここで「何について」「どう構造化するか」を定義する
4. **100〜200ソースが個人のスイートスポット** ─ それ以上はRAGも検討
5. **Markdown + 自分のPC + 好きなAI** ─ データ主権を手元に保てる
